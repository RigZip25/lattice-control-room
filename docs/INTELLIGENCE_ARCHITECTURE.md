# Intelligence architecture

## Principle

LATTICE is a system of governed models, tools and durable evidence — not one
opaque model. Language models may reason and generate; statistical models may
forecast; deterministic policies own authority. All three remain replaceable
and independently testable.

## Bootstrap Intelligence

The bootstrap layer prevents LATTICE from behaving like a junior marketer with
an empty memory. It contains:

- versioned universal marketing priors;
- category-specific prior libraries;
- product and Brand Package knowledge;
- market research and competitor-analysis procedures;
- acquisition, activation, retention and referral playbooks;
- creative strategy patterns and production recipes;
- channel-native operating knowledge;
- legal, platform, brand and capital constraints;
- counterexamples, anti-conditions and known failure modes.

Every knowledge artifact declares scope, provenance, version, confidence,
applicability, anti-conditions and supersession status. A retrieved document or
model answer is a proposal/input, not automatically a fact.

## Adaptive Learning

The learning layer consumes an immutable lineage:

`decision snapshot -> authorized execution -> canonical events -> attribution -> outcome window -> evaluation -> calibration -> proposal -> evaluated successor`

It supports several learning forms:

- forecast calibration;
- contextual bandit/ranking updates for bounded allocation;
- segment and MarketCell response models;
- creative pattern/fatigue learning;
- channel saturation and marginal-response models;
- activation and retention diagnosis;
- cross-market transfer estimates;
- anomaly and opportunity detection.

Learning output is a versioned proposal. It never mutates the artifact that
generated its own evidence.

## Metrics and event foundation

Before optimization, each Growth Contract defines canonical value events and
their semantics. The measurement layer records:

- workspace, brand, product and MarketCell scope;
- actor/account/channel/campaign/asset lineage;
- event and metric definition version;
- source/provider and ingestion time;
- occurrence time and observation window;
- consent/privacy class;
- deduplication identity;
- attribution method and uncertainty;
- quality: usable, degraded, invalid or confounded;
- observed vs inferred vs forecast semantics.

Channel metrics remain native, then map to product value events. LATTICE does
not optimize all products for clicks, registrations or ROAS.

## Opportunity discovery

Opportunity Scouts run bounded, scheduled research plans through tools and
provider adapters. Potential sources include public datasets, search demand,
competitor/product changes, community questions, reviews, content gaps,
advertising libraries, channel trends and a workspace's consented first-party
data.

Every source adapter declares terms/license, geography, freshness, cost,
coverage, rate limits and provenance. A Scout emits evidence and a falsifiable
opportunity hypothesis, never an untraceable recommendation.

External APIs are used when their information value justifies cost, latency,
privacy and dependency. Deterministic fixtures remain available for tests.

## Model lifecycle

Each model artifact records:

- model type and provider/runtime;
- exact version and feature/schema versions;
- training/evaluation data windows and fingerprints;
- workspace/brand/category scope;
- metrics and thresholds;
- known limitations and prohibited uses;
- status: draft, challenger, champion, retired or blocked.

Promotion requires replayable evaluation, leakage checks, segment-level
performance, calibration, safety/policy tests and rollback readiness. A model
may recommend; deterministic policy decides whether the recommendation is
eligible for capital or execution.

## Internal vs external learning

Workspace-local evidence trains or calibrates workspace-local artifacts by
default. Cross-customer learning is prohibited unless an explicit governance
contract defines aggregation, anonymization, consent, privacy and benefit. A
global model cannot expose or reconstruct another customer's strategy or data.

## Initial implementation order

1. Metric Definition Registry and canonical event envelope.
2. Immutable decision/outcome lineage.
3. Bootstrap Prior/Playbook Registry with provenance and anti-conditions.
4. Deterministic Scout and opportunity proposal pipeline.
5. Offline evaluator and champion/challenger registry.
6. Only then adaptive ranking/calibration against real outcomes.
